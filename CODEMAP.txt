- index.html: 입력+출력 단일 9열 표, 재고 Enter/모바일 Next(change) 완료 저장·정렬, stable key/revision, deterministic 발주 resolver, 실발주 단가·예상액·가격출처·누락사유, `sfaPriceHistory/latest` provenance/null/0 검증, immutable run `sourceTable` 원문CSV export, current/history pair ETag-CAS와 confirmed queue, 수동값 보호, Firebase 동기화, 인증 게이트. 환산 방향은 `1발주 단위 = 재고/사용량 N개`다.
- tests/orderhelper_static_checks.js: 기존 전체 정적/VM 회귀 + stable key/revision/명시 alias + AI latest top-level/fail-closed/수동값 보호 계약 검증
- tests/orderhelper_inventory_matching_regression.js: 입력 재고→출력 합계→current/history keyed payload, duplicate zone/id, legacy name, 0/blank, pair-CAS active+queued Enter revision fence, 신규품목/별명/동명이름/빈 배열 회귀
- tests/orderhelper_autosave_regression.js + tests/orderhelper_autosave_browser.py: draft-only PUT 0, Enter/모바일 Next current-history 동일 CAS body, Enter+change dedupe, 주방냉동 21행 연속 완료 저장, active+queued, timeout/부분실패 snapshot retry, reload 복구, quota/corruption fail-closed 회귀
- tests/orderhelper_single_grid_ledger_regression.js: 단일 표 정렬 2종, keyed focus/caret, 150행 입력 burst scheduler/render count, same-run retry/new-run append/duplicate/0/remote merge/누적 total, AI evidence 수동값 보호 회귀
- tests/orderhelper_p1_review_regression.js: mirrored physical-origin dedupe/sourceRunIds, stale retry latest-wins, CAS 412 remote merge, same-zone 입력순, 2,000-event bounded payload/성능 회귀
- tests/orderhelper_alias_arbitrary_save_regression.js + tests/orderhelper_alias_arbitrary_save_browser.py: 후보 밖 임의 별명의 버튼/비-IME Enter manual 확정, 타이핑·blur·IME PUT 0, current/history 동일 본문, 새로고침 재표시, 390px 회귀

- ORDER_LIST_ANALYSIS_HANDOFF.md: 발주 자동화 조사/진단 인계
- /root/SiteBot/main_auto.pyw: PC 다운로드/SFA 분석 실행자. `/monitor/main_pc/sfa_order_request`를 읽고 `/monitor/main_pc/status.sfa_order` 상태를 올린다.
- /sitebot/heartbeat/main_pc: OrderHelper의 SiteBot read-only preflight용 heartbeat evidence.
- /root/StoreBot/bot/order_excel_analyzer.py: SFA 엑셀 parser/compare 공용 경로. `SFA_ITEM_MASTER_ALIASES`는 SFA 원문 품목명 → OrderHelper MASTER 명시 매핑이며, 전역 threshold를 낮추지 않는다. g/벌크/배달용/내점용 같은 규격·용도 표기는 오매칭 방지 신호로 본다.
- /root/my-first-project/scripts/orderhelper_usage_inference.py: 재고 history + SFA 실발주 엑셀/비교 이력으로 `이전재고+입고-다음재고` 실사용량과 발주단위 환산을 추정해 `/unitInference/latest`에 올린다. 실사용 분석은 참고용이고, `/sfaActualHistory` 백필은 `--backfill-sfa-actual-history` 또는 `--bulk-backfill-local-sfa-actual-history` 명시 플래그가 필요하며, 수동 하루사용량 자동 write는 금지한다.

## 수정 시
- 코드 변경 전 APP_INTENT.md를 먼저 확인한다.
- 입력 동선, 계산식, SFA 대응, Firebase 경계가 바뀌면 APP_INTENT.md와 이 CODEMAP을 같이 갱신한다.
- 웹 UI 변경은 Playwright desktop/mobile screenshot, DOM smoke, Axe, empty state, 공장 PC/SiteBot evidence로 확인한다.
- 외부 사이트 live 조작/발주/주문 write는 read-only preflight와 분리된 별도 safety flow 없이는 진행하지 않는다.
- 라이브 반영 확인: `https://wk7007-wk.github.io/OrderHelper/` 에서 `APP_VERSION` 문자열 확인.
- Termux 감시만 바뀐 경우 OrderHelper 웹 배포는 필요 없다. PC/SiteBot 실행 경계와 Firebase 상태 경로만 검증한다.
- CLI 감시는 누락/정체/불일치 보고, `/unitInference/latest` 리포트 업로드, 코드/문서/배포 보정 역할이다. 엑셀 실발주 이력은 참고 배지/툴팁에 즉시 반영하지만, 발주 품목, 단위, 하루사용량 수동값, 환산, SFA 실발주 원본은 자동 확정하지 않는다.
- `orderSiteMappings`, `orderAliasMappings`, `orderUnitCorrections`, `orderManualItems`는 원천 SFA 행을 바꾸지 않는 사용자 보정 상태다. 로컬 저장소와 `/current`/`history` payload에 분리 저장하고 엑셀분석 요청 payload에도 포함한다. `orderManualItems`는 MASTER에 없는 사이트/SFA 항목을 원명 또는 임의명으로 추가한 내부 target 목록이다. `orderAliasMappingDrafts`는 후보/default 상태 read model이고, `effectiveOrderAliasMappings`는 `confirmed/manual` 우선 후 default를 분석 입력으로 쓰는 read model이다.
- 엑셀/SFA 누적 포인터: local `bbq_sfa_analysis_history`, current/history canonical `sfaOrderLedger`, `/sfaActualHistory` row를 ledger v2로 합친다. stable event id는 run+source row/raw identity를 기준으로 하며 eventAt/0/duplicate/alias/actual qty/amount/sourceRunIds를 보존한다. 같은 run retry는 최신 event merge, 같은 물리 원천 mirror는 한 event+복수 sourceRunIds, 다른 run은 append한다. current/history 쓰기는 두 node ETag read→ledger merge→동일 body pair PUT 순서다.
- AI 실사용 포인터: 브라우저는 모델을 호출하지 않는다. `buildAiUsageEvidence()`가 90일/2000 event canonical ledger에서 최대 100 samples/품목별 20 ids로 제한한 totals+raw ids+수동값 보호 정보를 기존 SFA request의 `aiUsageAnalysis`에 싣는다. worker 결과는 `/order/desk_q7m9r3a8/aiUsageAdvisory/latest` top-level 계약을 검증해 run/time/status가 붙은 참고 배지만 표시하며 invalid/unknown-only/older retry는 기존 값을 유지한다.
- 별명 보정 포인터: `orderAliasMappings`로 사용자사이트 별명→실발주항목+체크단위→발주단위 환산 검수 탭과 체크 입력 행 inline 보정을 공유한다. 최고 점수 후보는 default로 미리 쓰고, 사용자가 후보 선택 시 `confirmed`, 직접 숫자 입력 시 `manual`로 저장한다. payload의 `orderUnitToStockFactor`는 발주량에 곱해 체크/재고 단위로 바꾸는 품목별 값이다.
- 신규 원문 포인터: mapping 없는 SFA 원문+단위는 fuzzy 후보만 보여 주고 자동 확정하지 않는다. `confirmNewSourceAliasMapping()`의 명시 선택만 `bbq_local_new_source_aliases_v1`에 저장하며 `mergeLocalNewSourceAliases()`가 remote current hydrate 뒤에도 이 overlay와 기존 전체 mapping을 보존한다.
- 입력 완료 포인터: 배포 `20260717-07` / `0717.0323`. grid 입력 중 full render 지연·entryKey DOM 정렬·WeakSet change fence·모바일 header 정합은 유지한다. 2026-07-17 실접속 확인 개인폰·공장PC exact hash 두 개만 자동 진입하고, 메인PC는 PIN+factor 경로를 사용한다.
- 임의 별명 포인터: 후보에 없는 실발주 이름·단위는 별명 검수/inline의 `별명 생성` 또는 비-IME Enter에서만 `manual`로 확정한다. 일반 input/change/blur는 원격 저장하지 않는다.
- 엑셀 결과 수신 포인터: `loadSfaCompareLatest()`는 latest current, usage history, `sfaPriceHistory/latest`를 반영한 뒤 화면 resolver를 갱신한다. 엑셀 요청 전에는 `flushCurrentBeforeSfaAnalysisRequest()`가 pending 저장을 끝낸 뒤 최신 `buildSfaAnalysisPayloadState()`로 draft/effective payload를 만든다.
- 가격/원문 포인터: append-only `sfaAnalysisRuns/{runId}`가 canonical이고 정규화 행+선택 시트 전체 `sourceTable`을 보존한다. `원문CSV`는 이 표만 export한다. `sfaPriceHistory/latest`는 direct 단가 우선, 없으면 금액÷수량인 run-backed read model이며 alias를 자동 변경하지 않는다.
- 최신 완료 포인터: `20260715-02 Live integration: explicit new-source overlay + dirty-refresh preservation + pair CAS/lossless ledger/advisory latest`. 검증은 정적/VM 5종 + 로컬 Playwright intercepted pair-CAS/IME/XSS/listener DOM smoke + origin/master hotfix compatibility + inline syntax + diff-check; 실제 공장 PC/SiteBot worker와 live 화면/배포는 별도다.
- 로컬 SFA 이력 백필 전후 매핑 검증: `orderhelper_usage_inference.py --validate-local-sfa-history`가 `local_sfa_backfill_low_confidence_rows=0`을 요구한다. 2026-06-26 기준 `BBQ충진식패티(100g)(마일드)`와 `BBQ페퍼로니씬피자`는 `두마리치킨,파더스`와 별도 MASTER target이다.
- 보안 게이트: 실접속 확인된 개인폰·공장PC exact trusted hash 두 개만 network/GPS 전에 자동 진입한다. `/desktopAccess/registrationWindow`는 `autoApprove=false`, safe windowId, 최대 1시간, fresh 재조회가 모두 맞아야 하며 후보 PATCH에는 token 원문을 넣지 않는다. 이름/label/candidate만으로는 영구 허용하지 않고, window/network/candidate 실패 unknown은 기존 PIN+factor 잠금을 유지한다.
